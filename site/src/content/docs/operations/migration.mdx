---
title: Перенос панели на другой сервер
description: Проверенный порядок переноса базы, ключей, сертификатов и настроек с планом отката.
---

Этот сценарий переносит **панель** целиком, а не только список пользователей. Удобнее всего использовать встроенный архив `mikan backup`: он содержит базу данных, настройки установки, сертификаты, данные ноды и настройки платёжных адаптеров.

## 1. Подготовить старый сервер

1. Проверьте, что панель сейчас работает: `sudo mikan status`.
2. Сохраните отдельную копию пользовательского сайта, если он размещён в `/opt/mikan-2.0/data/panel/www`: сайт не входит в архив.
3. Создайте резервную копию:

   ```bash
   sudo mikan backup
   sudo ls -lht /opt/mikan-2.0/backups/
   ```

4. Запишите точную версию из `sudo mikan status` и имя созданного архива. Не публикуйте архив: в нём могут быть секреты.

## 2. Передать архив

Скопируйте архив по SSH на новый сервер. В примере замените имя файла и адрес:

```bash
scp /opt/mikan-2.0/backups/mikan-ГГГГММДД-ЧЧММСС.tar.gz root@NEW_SERVER:/root/
```

Перед передачей убедитесь, что SSH проверяет ключ сервера. Для дополнительной проверки файла можно вычислить SHA-256 с обеих сторон:

```bash
sha256sum /opt/mikan-2.0/backups/mikan-ГГГГММДД-ЧЧММСС.tar.gz
```

## 3. Подготовить новый сервер

1. Установите ту же версию Mikan 2.0, что и на старом сервере. Пока перенос не проверен, не направляйте пользовательский домен на новый адрес.
2. Убедитесь, что новый сервер поддерживает те же необходимые TCP/UDP-порты и что на диске достаточно места для архива, текущих данных и временной копии при восстановлении.
3. Скопируйте архив в каталог резервных копий:

   ```bash
   sudo mkdir -p /opt/mikan-2.0/backups
   sudo install -m 0600 /root/mikan-ГГГГММДД-ЧЧММСС.tar.gz /opt/mikan-2.0/backups/
   ```

## 4. Восстановить и проверить

Выполните восстановление на **новом** сервере:

```bash
sudo mikan restore /opt/mikan-2.0/backups/mikan-ГГГГММДД-ЧЧММСС.tar.gz
sudo mikan status
```

Команда проверяет архив перед восстановлением, останавливает контейнеры, сохраняет состояние назначения и возвращает его при ошибке. Секреты подключения к базе и версию уже установленного нового сервера она сохраняет; пользовательские данные, тарифы, настройки, ключи и сертификаты берутся из архива.

До переключения DNS проверьте:

- панель запускается, API и база доступны;
- на месте пользователи, тарифы, лимиты и настройки;
- ноды видны в **Ноды**, а их API доступны с нового IP панели;
- работает тестовая подписка и клиентское подключение;
- платёжные адаптеры и Telegram-бот доступны;
- установлены сертификат и секретный путь панели, а сайт восстановлен отдельно, если он был.

Если у панели изменился внешний IP или домен, обновите DNS/настройки и переоформите сертификат после проверки доступности. Для удалённых нод проверьте разрешённый адрес панели: некоторые конфигурации ограничивают API подключение по IP.

## 5. Переключить трафик и сохранить откат

1. В согласованное окно остановите панель на старом сервере через меню `mikan`, чтобы две копии не принимали изменения одновременно.
2. Переключите DNS на новый IP и проверьте панель, подписки и API извне.
3. Оставьте старый сервер и его архив выключенными, но не удаляйте, пока не завершится проверочный период.

**Откат:** если после переключения обнаружилась проблема, остановите панель на новом сервере, верните DNS на старый IP и запустите старую панель через её меню `mikan`. Старый сервер нельзя оставлять работающим одновременно с новым. Изменения, сделанные подписчиками уже после перехода на новый сервер, автоматически обратно не попадут; перед повторным переключением сначала перенесите актуальную базу.

## Важные ограничения

- Архив не включает собственный сайт из `data/panel/www`; скопируйте его отдельно.
- Перенос панели не переносит провайдера, firewall или allocation-правила. Проверьте их вручную на новом хосте.
- Не отправляйте полный архив или файл `.env` в публичные чаты. Храните копии с правами доступа только для root.
