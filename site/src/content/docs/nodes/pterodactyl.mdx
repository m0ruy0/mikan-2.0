Egg находится в репозитории: [`pterodactyl/egg-mikan-node.json`](https://github.com/m0ruy0/mikan-2.0/blob/main/pterodactyl/egg-mikan-node.json). Он запускает отдельный бинарник `mikan-node` обычным пользователем внутри контейнера. Docker socket, привилегии root и запуск Docker внутри игрового контейнера не нужны.

## Важное условие релиза

Egg скачивает только ноду из подписанного релиза: проверяет Ed25519-подпись манифеста и SHA-256 бинарника. Он намеренно откажется запускаться, если подписанный манифест не содержит секцию `node` для архитектуры `x86_64` или `aarch64`. Workflow сборки добавляет эти файлы в новые релизы; ранее опубликованный релиз автоматически не меняется. Сначала дождитесь релиза с node-asset, затем устанавливайте Egg на рабочем хостинге.

## Установка

1. В Pterodactyl откройте **Nests → Import Egg** и импортируйте JSON из репозитория.
2. Создайте сервер с образом **Python 3.12**. Контейнер должен иметь `curl`, `openssl`, `python3`, `base64` и `sha256sum`.
3. Назначьте **primary allocation** для API ноды и дополнительные TCP/UDP allocations для клиентских подключений. Провайдер должен пропускать протоколы и порты, которые вы собираетесь использовать.
4. В панели Mikan откройте **Ноды → Добавить ноду**. Укажите публичный адрес игрового хостинга и порт API, совпадающий с primary allocation.
5. Скопируйте одноразовый ключ ноды. В переменную `MIKAN_NODE_JOIN` вставьте только сам ключ, а не всю команду установки. Никому его не передавайте.
6. Запустите сервер. Скрипт проверит подпись релиза и checksum, загрузит бинарник нужной архитектуры, проверит совпадение API-порта и запустит ноду.
7. В Mikan проверьте статус ноды. Для каждого клиентского подключения назначайте только порты, которые провайдер выделил этому серверу.

## Ограничения

- Некоторые игровые хостинги выделяют только один порт, ограничивают UDP или фильтруют входящие подключения. Это ограничение провайдера, а не Egg.
- Панель должна иметь возможность подключаться по TCP к API-порту ноды; клиентские TCP/UDP-порты настраиваются отдельно.
- Возможности, требующие управления ядром хоста (например, TUN или изменение системной маршрутизации), внутри обычного игрового контейнера не поддерживаются.
- Тест CI подтверждает сборку и синтаксис startup-скрипта. Перед эксплуатацией проверьте Egg на реальном Wings-хосте своего провайдера.
